# Thread (Нить)

Нить — приложение для личной базы знаний. Вы пишете страницы-статьи в Markdown и связываете их ссылками прямо в тексте:
`[[HTTP]]`. Из ссылок складывается граф, а режим «Карта» показывает дерево изучения — что за чем учить.

Работает в браузере, устанавливается как приложение на компьютер и смартфон (PWA). Данные хранятся только на вашем
устройстве, сервер и учётная запись не нужны, сеть после первого открытия — тоже.

## Возможности

- **Страницы** с типом (тема, понятие, технология, проект, источник), тегами и статусом изучения. Редактор Markdown
  с предпросмотром и автодополнением названий после `[[`.
- **Связи из текста.** `[[Название]]` связывает страницы; ссылка на несуществующую страницу создаёт её.
- **Типы связей** — то, чего нет в Obsidian: `[[HTTP|требует знания]]`. Шесть типов: связано с, требует знания,
  является частью, использует, пример, альтернатива. Не знаете тип — ставьте ссылку без него.
- **Что изучить сначала.** На странице видна цепочка «Перед этим стоит изучить», изученное зачёркнуто.
- **Карта изучения** — дерево по связям «требует знания» и «является частью», с фильтрами, масштабом и экспортом в PNG и SVG.
- **Материалы** — конспекты, статьи, ссылки; один материал можно привязать к нескольким страницам.
- **Входящие** — сохраните материал «на потом», приложение подскажет подходящие страницы.
- **Обратные ссылки** — где ещё упоминается страница, с фрагментом текста.
- **Подсказки** — если название страницы встречается в тексте без ссылки, приложение предложит сделать её ссылкой.
- **Круглые отметки** — списки `- [ ]` переключаются нажатием прямо при чтении; интересующие страницы собираются в «Отмеченные».
- **Поиск** по тексту страниц и материалов с подсветкой найденного.
- **Резервная копия** в файл JSON и восстановление из него; выгрузка страниц в Markdown, импорт .md-файлов.
- **Мастер-пароль** (по желанию): данные на устройстве шифруются, приложение блокируется при бездействии.
- Светлая и тёмная тема, интерфейс для компьютера и смартфона.

## Установка

Нужен [Node.js](https://nodejs.org/) версии 20 или новее.

```bash
git clone <адрес-репозитория>
cd nit
npm install
```

### Попробовать

```bash
npm run dev
```

Откройте http://localhost:5173. На первом экране есть кнопка «Посмотреть на примере» — она загрузит небольшую
демонстрационную базу по веб-разработке. Удалить её можно в разделе «Настройки и данные».

### Собрать и пользоваться

```bash
npm run build
npm run preview
```

Откройте http://localhost:4173. В этом режиме приложение можно установить и использовать без сети:

- **Chrome и Edge на компьютере** — значок установки в адресной строке или «Настройки и данные» → «Установить приложение».
- **Android (Chrome)** — меню браузера → «Установить приложение».
- **iPhone и iPad (Safari)** — «Поделиться» → «На экран Домой».

### Разместить на своём сервере

Содержимое папки `dist/` — обычные статические файлы: их можно выложить на любой хостинг (GitHub Pages, Netlify,
Cloudflare Pages, свой nginx). Обязательно **HTTPS**: без него браузер не разрешит установку, работу без сети и хранилище.

## Ваши данные

- База лежит в закрытом хранилище браузера (OPFS) на вашем устройстве и никуда не отправляется.
- У каждого браузера и каждого адреса сайта — своя база. Открыли приложение в другом браузере или по другому адресу — база будет пустой.
- **Делайте резервные копии:** «Настройки и данные» → «Сохранить копию в файл». Браузер может удалить данные сайта при
  нехватке места или при очистке истории; приложение просит у него постоянное хранение и напоминает о копии, но файл надёжнее.
- Перенос на другое устройство — тем же файлом: «Восстановить из файла».
- Приложение открывается только в одной вкладке одновременно.
- **Мастер-пароль восстановить нельзя.** Если вы его забудете, зашифрованные данные останутся недоступными — поможет только
  резервная копия, сделанная заранее. Сама копия не шифруется: храните файл в надёжном месте.

## Как писать

| Что | Как |
| --- | --- |
| Ссылка на страницу | `[[HTTP]]` |
| Ссылка с типом связи | `[[HTTP|требует знания]]` |
| Ссылка со своей подписью | `[[HTTP|этот протокол]]` |
| Пункт с отметкой | `- [ ] прочитать` / `- [x] готово` |
| Остальное | обычный Markdown: заголовки `##`, списки, `**жирный**`, `` `код` ``, цитаты `>`, таблицы |

Связь без ссылки в тексте — кнопка «Связать» на панели связей. Клавиши: `Alt+←` / `Alt+→` — назад и вперёд,
`Ctrl+K` (`⌘K`) — поиск.

## Поддержка браузеров

Нужен современный браузер с OPFS и WebAssembly: актуальные Chrome, Edge, Firefox, Safari. Автоматические тесты идут
в Chromium; в Firefox и Safari приложение пока не проверялось — если что-то не работает, заведите issue. В приватном окне
и в браузерах без OPFS данные живут до закрытия вкладки — приложение предупредит об этом в настройках.

## Разработка

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Режим разработки с мгновенным обновлением |
| `npm run build` | Проверка типов и сборка в `dist/` |
| `npm run preview` | Запуск собранного приложения |
| `npm test` | Unit-тесты (Vitest) |
| `npm run test:e2e` | Сценарии в браузере (Playwright); перед первым запуском — `npx playwright install chromium` |
| `npm run bench` | Замеры производительности на графах до 10 000 страниц |
| `npm run icons` | Пересоздать значки приложения |

**Стек:** React, TypeScript, Vite · SQLite (WebAssembly) в OPFS с полнотекстовым поиском FTS5 · CodeMirror 6 ·
remark / unified · Cytoscape.js · Workbox · Web Crypto (AES-256-GCM) и Argon2id · Vitest, Playwright.

### Устройство кода

Слои: интерфейс → сервисы → репозитории → хранилище. База, поиск и шифрование работают в Web Worker и не тормозят интерфейс.

```
src/
├── core/            Логика без браузера и базы: ссылки [[…]], правила связей, обход графа,
│                    раскладка карты, шифрование
├── data/            Работает в Web Worker
│   ├── storage/       обёртка над SQLite и схема базы
│   ├── repositories/  SQL-запросы
│   ├── services/      страницы, материалы, связи, граф, поиск, копии
│   └── engine.ts      транзакции, шифрованное хранилище, блокировка
├── lib/             Клиент воркера, маршруты, Markdown → безопасный HTML
├── app/             Запуск и каркас экрана
├── features/        Экраны: страница, редактор, входящие, обзор, карта, поиск, настройки
├── components/ui/   Общие элементы интерфейса
└── styles/          Оформление; цвета и шрифты — в tokens.css
bench/               Генератор тестовых графов и замеры
tests/e2e/           Сценарии Playwright
docs/                Результаты замеров производительности
```

Где что менять:

| Что | Файл |
| --- | --- |
| Типы страниц, статусы, типы связей | `src/core/constants.ts` |
| Цвета, шрифты, отступы | `src/styles/tokens.css` |
| Цвета карты и экспорта | `src/features/map/MapSvg.tsx` |
| Демонстрационная база | `src/data/demo.ts` |
| Название и значки приложения, политика безопасности | `vite.config.ts` |

### Безопасность

- Содержимое заметок никогда не выполняется как код: HTML из Markdown очищается (DOMPurify), в сборке включены
  Content Security Policy без сторонних источников и Trusted Types.
- Все запросы к базе параметризованные; импортируемые файлы проверяются по формату и размеру.
- При включённом мастер-пароле на диске лежат только зашифрованные объекты, расшифрованная база — только в памяти.

Результаты замеров производительности — в [docs/EXPERIMENTS.md](docs/EXPERIMENTS.md).

## Ограничения

- Синхронизации между устройствами нет — только перенос файлом резервной копии.
- Картинки по внешним адресам не загружаются: вместо них показывается ссылка.
- Вложения (файлы, изображения) не поддерживаются.
